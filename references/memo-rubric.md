# IC Memo 评审 Rubric（v1 — 语料提炼）

来源：I2025–I2026 历史 memo 的评分实践与评审语言。本文件供三处使用：agent 成稿前自评、检查器语义依据、以及 IC Feedback 区的评分标尺声明。不含任何 deal 细节。

## 1. 评分标尺（1–10，log scale——9 分应比 8 分稀有 10 倍）

| 分 | 定义 | 实践含义 |
|---|---|---|
| 9 | Extremely good——赛道绝对头部候选 | 极稀有；类比行业公认头部产品的早期 |
| 8 | Very good——no-brainer | 不需要说服任何人 |
| 7 | Good | 值得投，主要评审人给出正面但具体的理由 |
| 6 | Worth investing, but on the fence | 可投但有明确保留意见；语料中最常见的分歧区 |
| 5 | Pass（不投） | 不再推进但保持关注 |
| 4 | 有红旗/坏历史/浪费时间 | 明确负面 |
| 2–3 | Really bad | 不再接触 |

打分纪律：**评分必须带理由**，语料惯例是"分数 +（一句具体依据 + 一句保留意见）"；条件升分显式写出（"Move to 7 when: 看到 X、Y、Z"）。

## 2. 过会 memo 的特征（agent 成稿自评清单）

1. **验证密度高**：关键声称带验证状态标注；至少一次独立验证动作（reference call / 产品实测 / 链上核对 / 注册库核对）写进 memo。
2. **数字密度高**：thesis 与 traction 的每条 bullet 带具体数字与时间窗；对标锚定（可比公司的规模/估值/结局）。
3. **诚实披露**：不利信息如实写（用户真实性未验证、需求循环、创始人兼职、估值偏贵）——语料显示这**提高**而非降低过会率，因为它让保留意见可讨论。
4. **生态协同具体化**：不是"有协同"，而是写出形态（部署/集成/volume 引导/牌照互补）与条件。
5. **最关键 underwriting question 点名**：一句"本案成立与否最终取决于 X"，让 IC 聚焦。
6. **条款结构清楚**：equity/token 双轨口径、特殊结构（blended/advisory/call option/volume trigger）触发条件写明。
7. **风险不走过场**：每条风险带缓解或监控信号；空泛的"市场竞争激烈"式风险是弱 memo 标志。

## 3. 弱 memo 红旗（检查与重写触发）

- TAM 直接抄 deck，没有自己的算术
- Traction 数字无净化（激励/空投/循环需求未拆）、无时间窗
- 无任何验证状态标注（全文没有"已验证/未能验证"字样）
- 团队节只有履历罗列，无核查、无全职状态
- 无生态协同分析，或只有一句口号
- 风险节少于 3 条或全是通用风险
- 估值只报数字，无对比（上轮/同类/我们的 entry level）
- 虚构 IC 成员评分或评论（**绝对禁止**——评分区只能留骨架）

## 4. House 尽调动作清单（Step 2 执行时对照）

| 动作 | 触发条件 | memo 中的呈现 |
|---|---|---|
| Reference call | 关键合作/客户/committed capital 声称 | "已与 X 直接确认"/"对方未回应" |
| 产品实测 | 产品可注册/可试用 | 同场景竞品对比，差距具体化（速度/功能） |
| 创始人见面 | 所有 deal | met in person / call + 印象 |
| 循环需求拆分 | committed 资金/量来自投资人或关联生态 | "circular, not independent demand" 标注 |
| 全职状态核查 | 所有联创 | 逐人标注；兼职列 open question |
| 链上核对 | crypto 标的 | 关键数字带 [链上] 标签 |
| 注册库核对 | biotech 标的 | ClinicalTrials.gov 阶段与终点比对 |
| 估值对比 | 所有 deal | vs 上轮、vs 同类、vs 我们通常 entry level |
| Refer 溯源 | 所有 deal | 引荐人/渠道写进元数据行 |

## 5. 行业 House View

当前语料每个行业样本 ≤2 份，不足以归纳行业级 house view。**待语料扩充后**（尤其同行业 ≥4 份含过会与被毙对照），再提炼写入对应 `industries/*.md` 的"House 视角"节。此前行业判断按各附录的通用框架执行。

## 6. Rubric 的使用方式

- **Agent 自评**：成稿后对照第 2/3 节逐条自查，弱 memo 红旗命中任意一条即重写该节。
- **检查器**：`check_private_output.py --mode memo` 的结构性检查以本文件为语义依据（结构能查的进脚本，语义性的靠自评）。
- **人工评审**：IC Feedback 区的评分标尺以第 1 节为准。
