# 输出格式与可读性规范（一级市场版）

目标：一级报告的可信度来自**可验证性透明**，可读性来自**结论前置、信息分层、数字规范**。撰写正文前必读本文件。

## 1. 报告头部（三件套，顺序固定）

依次为：**数据可得性声明框 → 结论框 → 标的速览表**。读者 60 秒内应获得完整决策信息 + 对这份报告"能信到什么程度"的准确预期。

**报告语言**：默认跟随用户请求语言；未明确时用当前对话常用语言。标题、章节名、缺失标记（"未获取到"/"Not obtained"）、判断标记（"我的判断"/"My view"）、免责声明统一语言。

### 1.1 数据可得性声明框（本技能第一硬性要求）

放标题之后第一屏，引用块格式：

> **数据可得性等级：B**
> 来源结构：链上可审计 45% ｜ 申报/审计 0% ｜ 公司一手材料 30% ｜ 第三方数据库 15% ｜ 未验证 10%
> 关键缺口：分 segment 收入拆分未获取到；token 解锁表仅官方博客口径，未经链上验证；活跃用户数无法区分空投农民

- **等级定义**见 `data-sources-private.md` 第 2 节（A/B/C/D）。
- **占比口径**：按报告中被引用的**关键数据点条数**估算（不是字数），合计 100%。
- **结论强度上限**：A/B 级可给明确投资观点；C 级观点必须带"以公司口径为准"的显式限定；D 级只能输出 preliminary screen，结论框写"信息不足，仅供初筛"。
- 英文等价：`Data availability grade: B`、`Source mix: on-chain verifiable X% | filings/audited X% | company-provided X% | third-party X% | unverified X%`、`Key gaps: ...`。

### 1.2 结论框

> **投资观点：Attractive / Neutral / Avoid / Track**（deep research 模式）
> **建议动作：Invest / Pass / Track，附条件**（IC memo 模式，如 "Invest，若估值 ≤ $X FDV"）
> （数据可得性 B ｜ 团队可信度 高 ｜ 置信度 中）
> 一句话论点：……（可证伪）
> 估值判断：本轮 $X 隐含 …… ，对照二级锚/轮次 comps 处于 …… 分位｜隐含 base case IRR/MOIC：……
> 关键验证点：未来 6–12 个月最重要的 2–3 个里程碑｜否决信号：出现什么直接 pass

**方向纪律**：投资观点回答"这个标的质地与价格"，建议动作回答"在本轮条款与我们的组合约束下怎么做"，两者可以不同（好项目贵估值 = Track）。

### 1.3 标的速览表

| 项目 | 赛道/主附录 | 阶段 | 本轮估值（口径） | 上轮估值 | 累计融资 | 核心 KPI（1–2 个） | 团队可信度 | 最近里程碑 |
|---|---|---|---|---|---|---|---|---|

每格带来源标签；crypto 标的估值一律注明 FDV 还是 equity。

## 2. 来源标签（正文通用）

关键数字后紧跟标签，五选一：

- `[链上]` — 链上可审计（DefiLlama/Dune/浏览器直读，或自跑查询）
- `[申报/审计]` — 监管申报、审计报告、临床注册库
- `[公司]` — 公司/项目方一手材料（deck、docs、官方博客、创始人访谈）——**原样引用，不转写成客观事实语气**
- `[第三方]` — 数据库或媒体（RootData/Messari/Crunchbase/The Block 等），注明出处
- `[未验证]` — 单一来源且无法交叉验证的传闻/报道

同一数字多来源冲突时列出对账结果，不悄悄选一个。附录必须有完整的来源与时间戳清单。

## 3. 章节写法（8Q 文风纪律，硬性）

（"8Q" 指 house 二级研究沿用的八问式 write-up 框架；本技能只继承其**文风纪律**如下，无需外部文件。）

1. 每章第一行：**「本章要点：」+ ≤2 句结论**（英文 "Key takeaways:"）。先给答案再给论证。
2. **第一人称单数负责制**："我认为 / 我的估算 / 我重算了"。不用无主语的"市场认为/大家觉得"逃避判断。
3. **每句带数字**；对标必须锚定参照系（"Solana 日活地址 ~X 万 vs 本项目 ~Y 千"）。区间优先于伪精度（"$8–10M ARR"、"20–30%"、"~" 标约数）。
4. **一份报告一个大类比**锚定认知（"the Stripe of X"、"链上的 Costco"），且类比要逐因素检验，不能只贴标签。
5. **篇幅不对称是设计**：辩论所在的 1–2 章给足篇幅（800–1,600 词），无争议的问题 1–3 句带过。深度跟着分歧走。
6. **自问自答**推进论证："我担心竞对降费吗？担心，因为……"
7. **对项目方口径保持怀疑**：自己重算 unit economics（take rate、单位毛利、fee 分配），并说明为什么官方口径可能失真（激励补贴、循环交易、关联做市）。
8. 不确定性词汇校准：高确信 = "基本确定/for sure"；真未知 = "无法判断/remains debatable"；期权性 = "算 option 不进 base case"。主动交代论点弱处。
9. 段落 ≤5 行；连续 3 段没有数字要警惕。表格就近，不集中堆章末。

## 4. 数字规范

- 币种一次性声明（"以下未注明均为 $M"）；千分位分隔；百分比 1 位小数。
- **crypto 估值口径纪律**：FDV 与流通市值必须区分标注，倍数默认用 FDV 算并注明；token 价格写明快照时间。
- **一级估值口径纪律**：注明 pre/post money、是否含 ESOP 扩池、equity 还是 token（或 equity+token warrant）。
- 精度匹配不确定性：估值区间写 "$120–180M" 不写 "$147.3M"。
- 每张表格带"来源/时间"列或表注。

## 5. 视觉件（文本渲染）

**估值对比图**（估值章必备）：

```text
一级轮次 comps        ▓▓▓▓▓▓▓ 100———160
二级锚折价后          ▓▓▓▓▓▓▓▓▓ 120———200
Token economics 检验     ▓▓▓▓▓ 90———140
综合区间 [100———————180]      本轮报价 150 ▼
```

**Industry mapping 分层表**（第三章硬性格式）见 `deep-research-template.md`。

**Unlock 压力表**（crypto 标的估值章必备）：未来 24 个月逐季新增供给占流通比，`token_economics.py` 输出。

## 6. 交付物清单

**交付给用户的只有报告文件本身**；中间产物一律内部留档。

| 产物 | 角色 | 说明 |
|---|---|---|
| 七章 deep research .md | 交付物（默认） | 用户指明时转 PDF/docx |
| IC memo .md | 交付物（IC 模式） | 含 deal 层；条款不全时留"待补条款"清单 |
| 估值假设 JSON | 内部留档 | scripts 输入，留工作目录供复算 |
| 检查器输出 | 内部留档 | 结果摘要写入报告附录 |
| 团队核查工作表 | 内部留档 | 敏感信息不进正文，正文只放结论与可公开证据 |

## 7. 长度与密度纪律

- Deep research 正文 3,000–6,000 词 + 10–20 张表；IC memo 2,500–5,000 词（判断浓缩，不是覆盖完整）。
- 每章自查："删掉哪一段读者不受损失？"能删就删。
- 附录收纳原始长表；正文只放被论证使用的数字。

## 8. 置信度自评表（末章必附）

| 维度 | 评分（高/中/低） | 说明 |
|---|---|---|
| 数据可得性 | A/B/C/D | 声明框同源 |
| 关键声称验证率 | | 已验证声称 / 全部关键声称 |
| 估值收敛度 | | 多方法区间重叠程度 |
| 团队可信度 | 高/中/低/无法评估 | team-diligence 输出 |
| **综合置信度** | | 低置信度 + 好观点 ≠ 大额度 |

## 9. 监控与验证登记

- 每条核心判断写成可到期验证的预测：基准值、区间/方向、验证日期、先行指标、失效条件。
- 更新报告时保留原预测与时间戳，只追加结果与误差归因，不得改写。
- 一级特有：**里程碑登记**（融资/上线/TGE/临床节点/牌照），每项标"已确认日程 / 团队目标 / 我的推测"三种确认状态。
