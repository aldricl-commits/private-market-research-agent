# Deep Research 模板：七章结构

严格按以下章节顺序输出。撰写前先读 `references/output-format.md`（声明框/结论框/文风纪律）。没有的数据按报告语言写"未获取到"或"Not obtained"，不留空表头。

格式约定：中文标题 `# 项目名 一级市场深度研究`，英文 `# Project Name — Private Market Deep Research`。副标题标"撰写日期 / 数据截止日 / 报告币种"，下一行声明 `行业附录: <主 slug>[, <次 slug>]`。

---

## 〇、一页速览（Executive Summary）

顺序固定：

1. **数据可得性声明框**（等级 + 来源结构占比 + 关键缺口，`output-format.md` 1.1）
2. **结论框**（投资观点 / 一句话论点 / 估值判断与隐含回报 / 关键验证点 / 否决信号）
3. **标的速览表**
4. 核心多空逻辑各 3 条（精炼、可证伪）

## 一、Business Description（业务描述）

本章要点先行。**8Q company overview 风格：300–600 词纯描述零观点**，判断留给后面章节。必含五件：

1. **产品做什么**：一段话讲清给谁解决什么问题；用一个类比锚定认知（全报告唯一大类比在此出现）。
2. **Business model 到收费方式层面**：take rate 多少、单价多少、抽佣怎么抽、订阅怎么分层。
3. **钱流走查（economics walk-through，硬性）**：谁付钱 → 钱经过谁 → 各环节分多少 → 落到标的手里的是什么收入 → 标的的成本花在哪 → 剩下什么 margin。用一张桥式表或流程句写完整闭环；crypto 项目须写清 **fee 在协议/LP/token holder/团队之间的分配**，以及 token 在这条钱流里到底承担什么功能（不承担就写不承担）。
4. **分 segment financials**：分业务线/分链/分产品的收入与毛利表（占比+增速）；一级数据常缺，缺就标"未获取到拆分"并给公司整体口径。

   | 业务线/segment | 最近期收入（口径） | 占比 | 增速 | 毛利率 | 来源标签 |
   |---|---|---|---|---|---|

5. **Operating metrics**：该行业附录 KPI 字典里的核心指标现值 + 趋势（表格，带来源标签与刷量核验结论）。

## 二、行业成长前景（Growth & Drivers）

本章要点先行，开头一句**加粗的增长结论**。

- **TAM 算术**：量 × 渗透率 × 单价/take rate，写出算式与每个因子的来源；**不引用公司 deck 的 TAM 数字作为自己的结论**（可列出并对账）。
- **增长驱动分解**：增长 = 行业量增 + 渗透率提升 + 份额 + 定价，各因子给证据与贡献量级。
- **渗透率对标**：对照他国/他链/相邻行业/上一代技术的渗透曲线定位当前位置。
- **周期位置**：crypto 标注当前市场周期与该赛道叙事热度（热度是风险不是论据）；biotech 标注技术平台成熟度。
- 落到**自己的增速区间判断**（"我预计该赛道未来 3 年 CAGR X–Y%，本项目若保持份额对应 …"）。

## 三、Industry Mapping（产业地图与竞争格局）

本章要点先行。**本章有两个硬性要求：分层表 + 二级锚列。**

### 3.1 价值链分层表（硬性格式）

| 层级 | 该层职能 | 代表一级玩家（阶段/最新估值） | **二级锚（上市公司/流通 token + 关键倍数）** | 标的位置 | 该层利润池判断 |
|---|---|---|---|---|---|

- **每一层"二级锚"列必须填**：有就列 ticker/token 名 + 当前关键倍数（P/S、FDV/fees 等）；没有就写"**无二级锚**"，并在表下说明该层估值传导路径（最近的锚在哪一层、怎么传导）。
- 标的所在层用 **加粗** 标记。

### 3.2 竞争格局

- 直接竞对表：一级竞对（融资/估值/关键 metric 对比）+ 二级竞对（若该层有）。
- 标的差异化主张 + **我的验证结论**（声称的差异化是否被数据支持）。
- 竞争烈度判断：该层是赢家通吃、双寡头还是长尾共存？依据是什么（网络效应/切换成本/同质化程度）。
- **上下层挤压检验**：上游（供给方/底层协议）和下游（渠道/聚合器）谁有议价权，会不会吃掉这层利润。

## 四、团队（Team Diligence）

本章要点先行。按 `references/team-diligence.md` 执行，正文放三件：

1. **核查表**：关键成员的声称履历 vs 验证结果 vs 来源（逐行）。
2. **红旗清单**：命中项逐条列证据；无命中写"未发现"并列已核查范围。
3. **综合评级**：高/中/低/无法评估 + 一句依据。加分项（连续成功创业者、核心技术真实作者、团队完整经历过上一周期）也如实列。

crypto 附加：团队/金库地址行为、匿名程度分级；biotech 附加：科学创始人的论文/专利真实贡献度。

## 五、估值对比（Valuation）

本章要点先行。按 `references/valuation-private.md` 执行，**至少两法 + 全部脚本计算**。必含：

1. 融资历史表（轮次/时间/估值口径/投资方/每轮隐含倍数）
2. 一级轮次 comps 表 + 标的隐含区间
3. 二级锚折价表（与第三章的锚呼应，折价取值写理由）
4. crypto：token economics 检验（FDV/流通、unlock 压力表、投资人成本 MOIC、红旗）
5. 反向检验：本轮/当前估值隐含什么（可证伪命题 1–3 条）
6. 退出情景表 → base/bull/bear 隐含 IRR/MOIC
7. 文本版估值对比图 + 综合区间

## 六、风险与反方论证（Pre-mortem）

本章要点先行。

**6.1 Pre-mortem（必做）**："三年后这笔投资失败了，最可能的 3 个原因"——至少一条直击本报告核心论点，每条给当前证据强度与监控信号：

| 失败情景 | 触发机制 | 当前证据强度 | 监控信号 | 证伪时点 |
|---|---|---|---|---|

**6.2 未验证声称的反转检验**：Step 2 中未能独立验证的关键声称，逐条评估"若为假，本报告结论是否反转"；会反转的显式压低置信度。

**6.3 赛道级风险**：监管（crypto 的证券认定/牌照、biotech 的审批路径、AI 的合规）、周期依赖、技术替代。

## 七、结论与监控

1. **结论**：复述结论框（投资观点 + 条件），回答"如果现在有额度，我会推进吗？下一步尽调最该查什么？"
2. **监控清单**：3–5 个指标，各带阈值与验证日期；至少一条上行验证与一条下行否决。
3. **里程碑登记**：未来 12 个月关键节点（融资/TGE/主网/临床读出/牌照），标确认状态（已确认/团队目标/我的推测）。
4. **置信度自评表**（`output-format.md` 第 8 节）。
