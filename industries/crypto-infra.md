## 1. 使用原则

- 基础设施的本质商业模式是**向使用它的应用和用户收"结算/计算/安全税"**（gas、DA 费、桥费、预言机调用费、RPC 订阅）。研究第一问永远是：**谁在为这条链/这个组件付真金白银，付了多少，为什么不走替代品**。
- 严格区分**真实需求费用**与**激励补贴产生的费用**：生态激励期的活跃度会在补贴停发后坍缩。任何费用/活跃度数字先做刷量核验（`data-sources-private.md` 第 6 节）。
- 区分**基础设施三种价值捕获路径**：(a) token 作为 gas/质押资产直接捕获（L1）；(b) 协议抽费但 token 捕获待定（多数中间件）；(c) 纯 equity 的 SaaS 式收费（RPC/节点服务商）。三者估值框架完全不同，不可混用。
- 生态是结果不是原因：不要把"生态项目数量"当成需求证据——查生态项目的真实用户与资金，剔除同一团队马甲项目。
- 技术差异化声称（更高 TPS、更低延迟、新共识）必须回答"这个差异对哪类应用是**必须**而非更好"，否则不构成需求论据。

## 2. 信息来源与链上核验

- **链级活跃度**：Artemis、Token Terminal、区块浏览器——日活地址、交易数、费用收入；一律取 90 天均值抹平快照冲高。
- **费用与收入**：Token Terminal 的 fees vs revenue 口径（fees=用户付的全部，revenue=归协议/token 的部分）；自查区块浏览器验证量级。
- **生态资金**：DefiLlama 链级 TVL 与桥入资金；桥入后留存率（30/90 天）比峰值 TVL 更有信息量。
- **开发者**：Electric Capital Developer Report 口径（全职开发者数）、GitHub 生态 repo 活跃度；剔除 fork 刷量。
- **去中心化程度**：验证者/节点数量与质押集中度（Nakamoto coefficient）、客户端多样性、sequencer 是否单点（L2）。
- **测试网数据不作需求证据**：测试网交互 99% 是空投农民，只能证明营销能力。
- pre-launch 项目的"生态承诺"（XX 个项目将部署）标 `[公司]`，上线后核对兑现率。

## 3. 价值驱动树

```text
基础设施价值 =
  上层应用创造的经济活动总量（GMV/交易额/结算量）
  × 该层的抽税率（gas/DA/桥费的有效费率）
  × 该基础设施在同层的份额（应用与流动性的选择）
  × 费用中归属 token/equity 的比例（价值捕获率）
  × 需求的补贴净化系数（剔除激励后的真实需求占比）
  − 安全预算成本（验证者/节点激励支出）
```

报告中至少回答：

- 上层经济活动是真实外生需求（支付、交易、游戏）还是资金内循环（挖矿套娃）？
- 抽税率的可持续性：竞争会不会把费率打到零（L2 之间的费用战、DA 的成本竞争）？
- 应用为什么选它：性能、成本、生态资金、还是投资人关系？迁移成本多高？
- 价值捕获：费用燃烧/分配给质押者的机制是否已上线，还是"未来治理决定"？
- 安全预算是否入不敷出：增发的质押奖励 > 费用收入 = 靠稀释买安全。

## 4. 核心 KPI 字典

| KPI | 计算/定义 | 研究用途 | 常见陷阱 |
|---|---|---|---|
| 日活地址（DAA） | 90 天均值，去重 | 需求基数 | 女巫地址；一人多址；机器人占比 |
| 真实费用（fees） | 用户支付的 gas/服务费总额 | 需求的货币化证明 | 激励期费用不可持续；自家 token 计价虚增 |
| 协议收入（revenue） | fees 中归协议/token 的部分 | 价值捕获现值 | 与 fees 混用；燃烧算不算收入要写明口径 |
| fees/TVL 或 fees/DAA | 单位资金/用户的费用产出 | 需求质量与同类对比 | 分子分母时间窗要一致 |
| 桥入净资金与留存 | 净流入及 30/90 天留存率 | 生态吸引力的资金投票 | 激励活动期间的热钱 |
| 全职开发者数 | Electric Capital 口径 | 生态供给侧先行指标 | 黑客松刷量；fork 项目重复计数 |
| TPS 利用率 | 实际 TPS / 理论上限 | 容量是否稀缺 | 理论 TPS 是营销数字；空块也算吞吐 |
| 质押率与集中度 | 质押量/流通量；Nakamoto 系数 | 安全性与抛压双面指标 | 高质押率也意味着解锁时的潜在抛压 |
| Sequencer/验证者收入 | MEV + 优先费 | L2/L1 的隐性收入池 | MEV 归属（协议/验证者/用户返还）口径不一 |
| 安全预算净额 | 费用收入 − 增发激励支出 | 经济模型自持能力 | 多数新链为深度负值，靠 FDV 稀释补贴 |

必须优先披露的 6 个指标：真实费用（90 天均值）、协议收入口径、DAA（去女巫说明）、桥入资金留存率、全职开发者数、安全预算净额。

## 5. Token economics 剖析

- **token 功能清单**：gas 计价？质押安全？治理？费用燃烧/分配？逐项写"已上线 / 白皮书承诺 / 无"。只有已上线的功能进估值，承诺的算期权。
- **供给侧**：创世分配（团队/投资人/基金会/社区占比）、unlock 表（`scripts/token_economics.py` 跑压力表）、增发率（质押奖励年化稀释）。
- **需求侧**：gas 消耗量、质押锁定需求、作为生态抵押品的需求——用链上数据分别量化，不接受"生态发展带动需求"的循环论证。
- **红旗阈值**（脚本自动标记）：内部人 >40%；TGE float <5%；12 个月供给增长 >100%；团队 vesting <24 个月。
- L2 特有：**排序器收入归属**——收入进公司 equity 还是 token，决定 token 是不是空气；许多 L2 的 equity 与 token 价值割裂，投资时必须写清投的是哪一层。

## 6. 估值方法（一级）

按 `valuation-private.md` 执行，本附录特化参数：

### 估值假设表

| 假设 | Bear | Base | Bull | 依据 |
|---|---:|---:|---:|---|
| 3 年后链上真实费用（年化） | | | | 对标同类链当前分布 |
| 费用归 token 比例 | | | | 机制是否上线 |
| FDV/fees 退出倍数 | | | | 二级锚分位 |
| 稀释后我们的实际回报口径 | | | | unlock 与解锁期 |
| 情景概率 | | | | 证据强度约束 |

1. **二级锚倍数**：主流 L1/L2 的流通 token 是本附录最直接的锚（FDV/fees、FDV/DAA）。锚的选取要同代际（模块化 vs 单体、通用 vs 专用）；报告列 3–5 个锚的倍数分布与标的隐含位置。
2. **轮次 comps**：近 18 个月同类基础设施私募轮 FDV；注意基础设施轮次估值受"上一个成功者"锚定严重（"下一个 Solana"溢价），显式指出叙事溢价成分。
3. **生态期权法**（早期）：估值 = 基础设施本体现金流价值 + 生态成功的期权；期权部分不进 base case，单独标注。
4. **反向检验**：本轮 FDV 隐含"上线后进入 fees 排名前 N"——对照现有排名第 N 名的真实费用量级，判断激进程度。

### Peer set 规则

- 同代际、同定位（通用 L1 / 以太坊 L2 / DA / 跨链）分开建表，不混桶。
- 至少纳入一个"失败者"（上一周期高 FDV 后费用归零的链）作 base rate 提醒。
- pre-TGE 标的的 comps 表必须同时给"可比项目上线 FDV"与"当前 FDV"两列——上线即巅峰是本赛道常态。

## 7. 护城河与竞争判断

| 维度 | 强证据 | 弱证据/反证 |
|---|---|---|
| 流动性/资金网络效应 | TVL 与深度让大应用无法迁走；清算基础设施依赖 | TVL 靠激励租来，补贴停即走 |
| 开发者生态 | 全职开发者数领先且增长；核心工具链绑定 | 黑客松人头；生态项目无真实用户 |
| 技术依赖锁定 | 应用深度使用其独有预编译/DA/账户抽象 | EVM 等价性=零迁移成本 |
| 品牌与安全记录 | 多年无重大事故的结算记录；机构默认选择 | 新链无记录；靠审计报告背书 |
| 成本结构 | 规模化后单位结算成本低于同类 | 低价靠补贴，非结构性成本优势 |
| 监管位置 | 基金会结构与去中心化程度足以抗证券认定 | 团队控制多签与升级权=中心化事实 |

定性判断必须绑定链上证据：声称"生态强"→ 桥入资金留存与开发者数据；声称"技术领先"→ 谁因此付费迁移。

## 8. 一级尽调红旗

- 主网多次跳票且每次伴随新叙事包装（roadmap 通胀）
- 测试网数据当真实需求宣传；生态项目多为同一批投资人的马甲
- 排序器/多签/升级权高度中心化但白皮书宣称去中心化
- 安全预算深度负值且无收敛路径——经济模型靠 FDV 信仰维持
- 团队把 equity 与 token 价值故意模糊（投资人拿 token warrant 但收入进 equity）
- 生态基金规模宣传 ≫ 实际已部署金额
- 对标叙事频繁切换（"以太坊杀手"→"模块化"→"AI 链"），跟着热点改定位
