# AI-Native 公司行业附录（一级视角）

## 1. 使用原则

- 先分层再研究，三层的经济模型完全不同：
  - **基础模型层**：资本密集（训练成本）、技术迭代风险极高、变现靠 API/订阅/授权——本质是"资本+人才军备竞赛"，少数赢家。
  - **Infra/工具链层**：卖铲子生意，随整体 AI 支出增长，但被云厂商与模型厂原生功能双向挤压。
  - **应用层**：传统软件规律 + AI 增量；核心问题是"模型能力提升会不会吞掉这个产品"（wrapper 风险）。
- **ARR 质量甄别是本附录第一功课**：AI 公司的 ARR 高增长常混入试点合同（POC，不续约）、用量补贴、年化单月峰值。拆出 committed ARR、试点占比、logo 留存后再谈倍数。
- **毛利率是照妖镜**：推理成本吃掉的毛利决定这是软件生意（70–80%+）还是算力转售生意（20–40%）。毛利结构比增速更能区分公司质地。
- 增速的分母效应：从 $1M 到 $10M 的 10 倍与从 $10M 到 $100M 的 10 倍是两个难度等级；对比 comps 时按 ARR 量级分档。
- 技术领先性声称一律要求可验证证据：公开 benchmark（注明可刷）、论文、客户可验证的效果数据；"内部评测领先"标 `[公司]`。

## 2. 信息来源与核验

- **收入与客户**：data room 的 committed ARR 明细（合同期限、试点标记）；公开 case study 的客户逐一验证（对方是否也公告/可否试用产品验证）。
- **产品实测**：能注册试用的一律试用；API 定价页与变更历史（降价史=竞争压力的直接证据）。
- **算力**：融资中算力 credit 占比（拆开标注，credit 不是现金）；与云厂商的承诺消费协议（既是资源也是负债）。
- **人才**：LinkedIn 员工数趋势与研究员名单；核心研究员的论文记录（Google Scholar）；离职流向。
- **技术真实度**：GitHub（开源组件的真实活跃）、Hugging Face（模型下载与社区）、论文复现情况；benchmark 对照第三方复测（LMArena 等，标注局限）。
- **烧钱推算**：员工数 × 人均全成本 + 已披露算力支出——与融资额对照得出 runway 推算，标"我的估算"。

## 3. 价值驱动树

```text
AI 公司价值 =
  可服务工作流的价值总量（该场景的人力/软件支出池）
  × AI 渗透率提升曲线（任务可自动化比例 × 采纳速度）
  × 标的份额（分发渠道 × 产品迭代速度）
  × 定价捕获率（按席位/按用量/按结果的定价力）
  × 稳态毛利率（推理成本曲线 × 模型效率进展）
  × 留存质量（工作流嵌入深度，vs 模型升级的替代风险）
  − 持续研发与算力再投资
```

报告中至少回答：

- 客户买的是什么：效率工具（可替代）还是嵌入工作流的系统（有粘性）？净金额留存的证据？
- 模型层升级（下一代通用模型）会增强还是吞掉这个产品？（wrapper 检验）
- 毛利率现在多少、推理成本下降曲线下稳态多少？定价会不会同步被压？
- 增长靠产品还是靠 AI 预算潮：客户是从"创新预算"还是"核心预算"付费？（前者退潮快）
- 数据飞轮是真是假：用户数据是否真的回流改进产品，有没有量化证据？

## 4. 核心 KPI 字典

| KPI | 计算/定义 | 研究用途 | 常见陷阱 |
|---|---|---|---|
| Committed ARR | 有约束合同的年化经常收入 | 收入质量基准 | 试点/POC 年化冒充；用量单月峰值年化 |
| 试点转化率 | POC → 付费合同比例 | 产品真实价值 | 只报成功案例 |
| 净金额留存（NRR） | 同 saas 口径 | 粘性与扩张 | 早期客户少，NRR 无统计意义时如实说 |
| Logo 留存 | 客户数留存 | 底层粘性 | 大客户流失被新签掩盖 |
| 毛利率 | 含推理/托管成本 | 生意本质甄别 | 把推理成本记到研发；用补贴价算 |
| 推理成本/收入 | 单位经济核心 | 稳态毛利推演 | 模型降价与用量增长的赛跑 |
| 人均 ARR | ARR/员工数 | 效率与自动化含量 | 外包与代理成本不在员工数里 |
| 烧钱与 runway | 月净消耗/现金 | 生存约束 | 算力 credit 到期悬崖 |
| 算力承诺 | 云合同总额与期限 | 资源与负债双面 | 承诺消费未用完的违约风险 |
| 研究产出 | 论文/模型发布节奏 | 基础模型层的竞争力 | 数量≠质量，看引用与复现 |
| API 价格变动 | 单位 token/调用价格史 | 竞争烈度直读 | 降价 50%+/年是常态，模型层尤甚 |

必须优先披露的 6 个指标：committed ARR（拆试点）、毛利率（含推理成本口径）、NRR 或 logo 留存、烧钱与 runway、算力承诺结构、（基础模型层）研究团队与产出。

## 5. 经济模型剖析（AI 特有）

- **推理成本三变量**：模型大小路线（蒸馏/小模型化）、硬件成本曲线、用量增长——毛利率的稳态推演必须写出三者的假设。
- **定价模式迁移**：按席位 → 按用量 → 按结果（outcome-based）的行业趋势；标的现在哪一档、迁移对收入的影响（按结果定价理论上限高但波动大）。
- **算力 credit 会计**：融资额中 credit 部分单列（不是现金，有指定用途与到期）；credit 消耗完的真实成本悬崖排进里程碑。
- **人才结构**：研究/工程/GTM 比例与阶段匹配度；核心研究员的持股与竞业（AI 人才流动性极高，单点依赖是真实风险）。
- **开源策略**（若有）：开源引流 → 商业版变现的转化证据；纯开源无变现路径的按期权处理。

## 6. 估值方法（一级）

按 `valuation-private.md` 执行，本附录特化：

### 估值假设表

| 假设 | Bear | Base | Bull | 依据 |
|---|---:|---:|---:|---|
| 3 年后 committed ARR | | | | 分母分档的增速 base rate |
| 稳态毛利率 | | | | 推理成本三变量 |
| NRR 稳态 | | | | 工作流嵌入证据 |
| 退出倍数（EV/ARR） | | | | 二级软件锚+AI 溢价核验 |
| 情景概率 | | | | 证据强度 |

1. **ARR 倍数 comps**：一级 AI 轮次的 EV/ARR 分布（按 ARR 量级与增速分档）+ 二级软件锚（上市 SaaS 高增长组）——AI 溢价部分显式量化（"本轮 40x ARR vs 二级高增长组 12x，溢价 3.3x，需要什么来消化"）。
2. **轮次 comps**：近 12 个月同层同量级（AI 估值周期极快，时间窗比其他赛道更短）；标注"AI 预算潮"周期位置。
3. **基础模型层特化**：收入倍数失真（收入远滞后于能力投资），辅以"军备竞赛存活框架"——资本储备/年烧钱、人才密度、分发绑定（云/终端）三要素打分，对照该层已出清玩家的 base rate。
4. **反向检验**：本轮估值隐含的 3 年后 ARR（按二级倍数回落假设倒推）→ 需要的增速 vs 分档 base rate 分位。

### Peer set 规则

- 分层建表（模型/infra/应用），应用层再按垂直分。
- ARR 量级分档（<$5M / $5–20M / $20–100M / >$100M），跨档倍数不可比。
- 二级锚用高增长软件组，标注 AI 标的的毛利率差异调整。

## 7. 护城河与竞争判断

| 维度 | 强证据 | 弱证据/反证 |
|---|---|---|
| 工作流嵌入 | 替换需迁移数据/流程/集成，NRR 高且续约有记录 | 单点功能工具，模型升级即可替代 |
| 专有数据飞轮 | 独占数据源 + 回流改进有量化证据 | "数据飞轮"仅是叙事，公开数据可复现 |
| 分发渠道 | 绑定云市场/终端/生态的独占入口 | 纯自获客，CAC 随竞争恶化 |
| 人才密度（模型层） | 核心方向的顶尖研究员聚集且稳定 | 明星挂名，实际流失 |
| 规模效应 | 用量→成本优化→价格→用量的飞轮已现 | 规模带来的是算力账单不是优势 |
| 切换成本（infra） | 深度集成进训练/部署管线 | 接口标准化，一键迁移 |

**Wrapper 检验必答**：下一代通用模型原生具备该产品 80% 能力时，客户为什么还付费？答案只能是数据、工作流、分发、合规其中之一，且要有证据。

## 8. 一级尽调红旗

- ARR 口径混杂（试点年化、用量峰值年化）且拒绝拆分
- 毛利率不披露或把推理成本记入研发
- 融资额宣传含大额算力 credit 未标注
- benchmark 只引用自测口径；第三方复测显著缩水
- 客户 logo 墙无法验证（对方无公告、无法试用验证）
- 核心研究员在融资官宣后 6 个月内离职（查 LinkedIn 时间线）
- "自研模型"实为开源微调且未披露（技术尽调可验）
- 创始人同时运营多个 AI 项目，精力与 IP 归属不清
